# ADR-0002: 世界生成策略（Bevy 迁移版）

状态：接受

日期：2026-10-19（自原 Godot 版 ADR-0002 2026-07-08（M3 修订 2026-07-11）迁移改写；本版已合并 M3/ADR-0004 的 Block 优先生成修订，为最终形态）

## 上下文

需要为 2km × 2km 的有限世界地图设计生成策略。地图需要在玩家行走时动态实例化物体，同时保证存档可完整恢复探索过的内容。低端显卡（2-4GB VRAM）约束下不能同时加载过多物体。实现语言由 GDScript 改为 Rust/Bevy。

## 决策

### 总体策略：混合两阶段生成（不变）

```
开局（<1秒）: seed → 扰动网格 → Block 合并 → WorldGrid → LayoutGraph（紧凑拓扑）
                            ↓
行走时: 玩家位置 → 确定活跃区块 → 实例化物体
                            ↓
远离时: Chunk 卸载（despawn_all）→ 释放 GPU 资源
```

### 第一阶段：拓扑预生成（开局时）

- 由 seed 一次性生成完整路径网络拓扑（Block 优先生成算法，见 ADR-0004）
- 输出紧凑的 **LayoutGraph**（Rust 结构体，serde 序列化），包含：
  - 路径的几何骨架（中心线+宽度）
  - 节点位置（路口、广场）
  - 每个 Block 的用途标签（老城区/公寓/厂房/广场/树林）
  - 地图边界坐标
- 同时输出 **WorldGrid**（2D 网格中间结构），记录每个 cell 的 block_id、是否为道路、是否为路口，用于快速查询和存档序列化
- 这段计算在开局时瞬间完成（<1秒）；布局图本身不含任何 3D 网格实例，内存占用极小

### 第二阶段：实例化流式加载（行走时）

- 世界按 **Chunk** 划分网格，单个 Chunk 尺寸：50m × 50m
- 2km × 2km 地图 ≈ 40×40 = 1600 个 Chunk
- 只对**玩家周围不对称范围内的 Chunk** 进行实例化（第一人称视角优化）：
  - 加载半径：前方 4 个 Chunk（约 200m 可视范围），后方 2 个 Chunk（防转身卡顿）
  - 同时加载的 Chunk 数 ≈ 55 个（峰值）
- 玩家远离的 Chunk 被卸载释放 GPU 内存（Bevy 0.20 的 `despawn_all` 批量 despawn 已优化，10 万实体 2.07ms）
- Bevy 侧 Chunk 系统：Chunk 管理器为 `Resource`，每个 Chunk 的实例化物体为 entity group；GPU-driven rendering 自动生效

### 路径网络生成算法：Block 优先生成（最终形态）

- 地图被划分为**街区单元（Block）**，每个 Block 之间是街道
- 生成顺序：先生成 Block，剩余 cell 自然成街道（**Block 为正形，街道为负形**）
- Block 按 BlockType 差异化合并规模：
  - 老城区 1×1（约 50×50m）
  - 公寓 2×2 或 3×3（约 100-150m）
  - 厂房 4×4 或 5×5（约 200-250m）
  - 广场 1×1
  - 树林 1×1（边缘过渡带）
- 合并区域内部的网格边被物理删除（大街区内部无道路，玩家不可进入）
- 约束条件确保所有街道形成环路（无死胡同）
- 每个街区分配一种建筑风格，或标记为树林/广场

### 物体放置规则

- 每个 Chunk 的物体放置由 seed 和布局图共同决定
- 建筑沿街道边缘放置（沿 edge 统一算法），高度与风格匹配对应街区类型
- 建筑按 BlockType 差异化参数（老城区 4-6m 方形 / 公寓 25-40m×12-14m / 厂房 50×50m）
- 碰撞策略：负形街道模型——沿 Block 生成不可见实心碰撞实体，建筑和树都不带碰撞体（详见 ADR-0004）
- 树木在街道边和开放空间放置，密度受季节参数影响
- 放置信息在加载时即时计算（确定性 seed 算法，无需存储）

### 存档与恢复（结构不变，serde 实现）

- 存档仅存储：**seed + 地图尺寸 + 季节（独立枚举值）+ 已探索 Chunk 位图 + 玩家位姿**
- 恢复时：从 seed 重新生成 LayoutGraph → 根据位图标记玩家位置 → 加载周围 Chunk
- 已探索但当前不在加载范围内的 Chunk 在恢复时跳过实例化，行走靠近时再加载
- 恢复速度要求 <1s

## 备选方案

- **纯实时生成（无预生成）**：每一步都随机生成，但存档无法保证一致性——已否决（沿用原项目）
- **全量一次性生成所有物体**：1600 个 Chunk 的物体在低端显卡上不可行——已否决（沿用原项目）
- **原 Godot M2"网格扰动→边→识别 Block"算法**：Block 尺寸均一化、厂房溢出——已被 Block 优先算法取代（沿用原 ADR-0004 决策）

## 后果

- 需要实现 LayoutGraph/WorldGrid 的 Rust 结构体（serde 支持，供存档复用）
- 需要实现 Block 优先生成算法（移植原 `path_network_generator.gd` + `world_grid.gd` 逻辑）
- 需要实现 Chunk 系统和流式加载/卸载逻辑（Bevy entity spawn/despawn）
- 需要实现确定性 seed 放置算法（`rand_chacha::StdRng::seed_from_u64(seed)` + chunk 坐标哈希；禁止 thread_rng 穿入生成路径）
- 几何验证测试（OVERLAPS=0、同 seed bit-exact）作为 Rust 单元测试保留
- 配合存档系统，恢复时重建布局图的速度要<1s
